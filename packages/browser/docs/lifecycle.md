# 运行生命周期

共享本机监听和插件连接属于扩展实例。首次控制时，本包通过 `call.resources.register` 登记当前真实 run 的冷 RunScope，再申请目标锁和远端 lease；无需人工认领。

同一 run 可以重入，其他 run 的目标冲突明确失败。已知多目标先按稳定身份原子保留，不能持锁等待另一个 run。等待事件的 get 不占住触发动作需要的命令队列。

run 正常结束、失败和取消都经标准资源 `dispose/closed` 收尾。本包取消等待和在途动作，逐项收尾已经登记的输入、视口和 debugger 状态，收到真实远端关闭证据后才释放控制；本地请求发出或 socket 关闭不等于远端已经关闭。未确认时保留身份和诊断。

停用仅关闭本包监听和受管控制，不结束用户浏览器，不关闭普通结果标签。共享空闲连接不会永久阻止停用；活跃 run/方法/脚本继续按平台占用规则处理。重启不恢复旧 Promise 或重放旧动作。

原生用户 `onDetach` 已证明本包调试通道关闭。本包不会重新 attach 以释放按键或覆盖用户的新控制；不能继续确认的输入效果通过 `unconfirmedControls: true` 保留，不能称为按键已经释放或网站操作回滚。

方法在本地准入、等待租约或命令排队阶段超时，报告 `dispatched: false`、`effect: "none"`。实际动作发送后才使用可能的 `effect: "unknown"`；取消排队不会在稍后偷偷执行该动作。handoff 和对话框控制保留独立控制通路。

正常 `tab.close()` 或 `selected.management.tabs.close(id)` 只关闭本次明确选择的标签。关闭前确认释放该标签的本包按键、鼠标、视口和 IO；确认真实关闭后才撤掉它的所有权与等待器。同运行里的其他标签继续可用。与之并发的真实用户取消仍按用户接管处理；不能把任意 debugger 断开都解释为正常关闭。
