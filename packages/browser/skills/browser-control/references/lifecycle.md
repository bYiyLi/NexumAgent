# 浏览器操作生命周期与恢复

此参考仅在用户接管、取消、跨 Run 重入、控制争用或关闭操作出现问题时读取。

- Nexum 的浏览器控制由当前 Run 管理，资源和目标锁随着实际执行生命周期释放。正常结束、取消或超时不代表站点操作自动撤销；不要据此重放已发送动作。
- 如果另一 Run 占用同一标签，按当前返回的争用状态处理；不绕过占用、不通过再次获取同一 Tab 强行抢占。当前 Run 中其他已确认完成的独立动作仍保留。
- 用户主动接管或 Chrome 原生调试通道断开时，当前控制句柄可能失效；先停止自动操作。需要继续时，在真实用户许可和新运行/控制身份有效后重新发现 Tab、观察页面，不复活旧 Locator/ref/Dialog。
- `dispatched: false` 且 `effect: "none"` 只在实际系统证实未下发时表示无动作；超时、取消或断连导致 `effect: "unknown"` 时先回读状态，不自动重复点击、上传、支付或提交。
- Run 取消已接纳但仍在收尾时，读取原 Run 状态；仅在终态及对应实际关闭证据成立后报告完成。有界观察到期不会取消原清理任务，不重复启动 Run。
- 关闭标签只针对用户请求的明确目标；未经请求不要结束用户浏览器或删除原有标签。只有收到真实完成/关闭证据才称已释放控制。

如需排查底层清理、debugger、RunScope、端口或恢复日志，按需读取 [内部诊断依据](diagnostics.md)。
