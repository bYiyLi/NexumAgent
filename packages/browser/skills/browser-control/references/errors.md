# 浏览器错误、恢复与验证

## 区分错误层级

- **参数或目标错误**：`INVALID_ARGUMENT`、`INVALID_TARGET`、`AMBIGUOUS_TARGET`。检查方法签名、元素类型、唯一性和页面状态；不要因为文案包含 Worker 就直接判断扩展进程崩溃。
- **能力或权限问题**：`CAPABILITY_NOT_ALLOWED`、`POLICY_DENIED`、`USER_TAKEOVER` 等。以本次注册能力及实际授权为准；缺方法不能猜调用，拒绝不能绕过。
- **引用/上下文过期**：`STALE_REF` 等。重新发现标签、观察元素、获取新的 ref 或上下文；不能复用旧 ref。
- **连接或运行资源问题**：`EXTENSION_OFFLINE`、`PORT_IN_USE`、争用/超时等。报告哪个环境、浏览器、连接阶段、实际检测结果；只有确认连接已断开时才按 [连接与限制](connection.md) 处理。
- **Agent 脚本层**：`worker_script_failed` 是 Agent Worker 执行失败的泛化结果，**不足以证明 Chrome 扩展 Worker 崩溃**。保留原始错误、Run ID 和可获得的操作记录，检查有无已发生副作用。
- **业务未验证**：`INPUT_UNCONFIRMED`、`EXPECTATION_UNCONFIRMED` 及 `effect: unknown`。已发送的点击/提交可能生效；先回读页面，不能自动重复执行。

只根据实际返回的错误码和诊断描述判断。不能确定内层根因时写“尚未确认”，不编造更具体的错误码、重试保证或异常来源。

## AI 恢复路径

1. 记录已知的 `operation`、原始错误码/消息、`runId` 与浏览器/标签目标（若响应包含），确认是否在浏览器方法内部失败，还是脚本提交/序列化阶段失败。
2. 如果输入校验在分发前明确失败，可以修正参数；如果输入已下发或是否下发不明，先只读核对目标效果。重复提交、重复点击和重复下载可能带来副作用。
3. 页面与连接仍正常时，只修改失败的那一步，不刷新整个页面；若页已导航则重新定位元素。
4. 真正的断连或 lease 失效，需要重新发现/授权后继续；已完成的独立动作保留原结果。用户接管时停止自动控制。
5. 最终对用户说明：已确认完成、明确失败、效果未知各有哪些；错误码不能替代业务结果。

## 反馈的必要内容

向 AI 返回的诊断应包含可用的实际事实：失败层级、调用方法、目标、可重复观察到的状态、可能已发生的效果及恢复方向。底层信息缺失就承认缺失。不要只返回 `worker_script_failed` 或“稍后重试”而不说明范围。

内部故障的端口/连接代次/资源收尾证据在 [内部诊断依据](diagnostics.md)，只在需要深入排查时读取。

本 Skill 是**当前行为使用指南**，并不宣称运行时已经实现新的结构化错误字段或自动恢复功能。
