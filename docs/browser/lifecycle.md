# Nexum browser 生命周期

## 实例启动与就绪

通用扩展加载器静态检查 npm 身份/版本、exports、协议、namespace、权限及四类贡献，再调用 `createExtension(host)`。一份 Agent/profile 仅一个 browser 实例；并发初始化共享结果，跨 profile 不共用变量或连接。

工厂先创建冷的 BrowserService 控制对象，尚不 listen、不创建 WS、定时器或系统副作用；用 `host.resources.register({kind:"browser-service",value:service})` 登记后，检查资源/host signal，再启动 loopback 服务。服务确认实际 listening、协议路由和清理入口就绪后才返回方法表。后续公共准备/Schema/资料失败时，核心可凭登记关系清理；工厂的未登记临时内容自行 finally 收尾。没有浏览器连接不是初始化失败；端口冲突、错误环境/配置或协议准备失败只保留该实例诊断，不假装服务已上线。

`ManagedResource.closed` 表示监听器、全部受管 socket/定时器及启动路径已真正关闭；`dispose()` 是幂等请求，不能把调用完成冒充实际关闭。初始化过程中同时取消/停用、listen 异步完成或返回方法失败，仍不能留下无人管理端口。

## 实例资源与单次运行

| 对象                                   | 归属                   | 释放时机                                                        |
| -------------------------------------- | ---------------------- | --------------------------------------------------------------- |
| 本机监听、插件连接、连接注册和必要保活 | host 实例共享资源      | 扩展停用/替换或 Agent 退出；一次 run 取消不触发                 |
| 标签页元数据、修订、能力               | 当前连接内存           | 断连立即失效；新连接重新读取                                    |
| 操作锁、等待器、订阅、临时后台读页     | 当前 call/run          | 方法/运行结束、取消、期限或目标失效后真实收尾                   |
| 新建普通/结果标签                      | 用户浏览器中的真实对象 | 按显式 close 或临时用途规则；不因 run 返回关闭用户原有/结果标签 |
| 产物和下载后的固定资源                 | Nexum 产物/资源        | 按平台保留、到期和当前权限，不随观察结束消失                    |
| 持久安装身份/偏好/稳定插件文件         | 包的 profile 目录      | 显式维护/卸载选择；不保存旧活跃控制句柄                         |

客户端门面、locator 等是本次脚本对象；下一次 run 使用实际公开身份重新获取，不自动恢复旧 JS 局部变量。用户浏览器的登录、已填内容和页面状态在浏览器中自然保留。原生 Node 模块缓存不承载当前调用者或全局当前标签。

## 方法、锁与并发

每次实际 I/O 通过公开方法表进入，核心先登记 operation 和真实 call，扩展再检查当前访问权、signal/deadline、目标及连接/页面代次。公开门面不能自报 runId 授权；WS action 上的 runId/operationId 由当前 call 填入。

同标签页的写操作及需要 CDP 控制/附着的操作按 runId 自动互斥；当前运行可重入，另一运行返回 TAB_ALREADY_CLAIMED，不要求用户认领。安全的观察也须与导航/写动作按确定顺序提交，不能拿旧快照当成新现场。跨标签操作对已知目标集合按稳定复合身份顺序原子保留，全部成功后才有副作用；失败仅撤回本次新保留，不丢弃原有锁。动态追加目标遇到冲突立即返回 TAB_ALREADY_CLAIMED，不持锁等另一个 run，避免循环等待。平台运行容量沿 Nexum，浏览器通道额外限制为每连接最多 64 个在途动作、单目标串行提交有限浏览器命令；导航/download 等待不长期占住命令队列，等待条件由先建立的监听完成；超量返回 QUEUE_FULL，不另建全局运行器队列。

每个 run 的首次控制 I/O，扩展从真实 call.context.runId 查找或创建本包 RunScope；并发首次创建共享同一登记结果。RunScope 是扩展自有 ManagedResource，先用 call.resources.register 登记冷对象，再取得目标锁、开启远端控制租约、attach CDP/监听或设置视觉状态。它保存本 run 的目标、按键、等待器、订阅、临时标签、视口和视觉标记，不能保存旧 call 服务给其他 run 使用。操作调用结束不释放整个 RunScope；本次 run 的正常收尾、失败或取消通过公共资源 dispose 触发相同清理，不需要 onRunEnd 回调、读取内部 RunStore 或监听核心私有事件。

RunScope.dispose 先关闭该 run 的新动作准入，取消等待/在途动作、释放本包按键和临时覆盖，发送远端 lease_end 并等待本包 CDP/监听/active 状态清理事实，关闭临时后台标签，最后释放锁；用户原有/新建普通/结果标签保持打开。清理不能把取消前尚未发生的 markDeliverable 补成成功。结果标记只表示该标签被脚本明确标为交付或结束控制，不表示 run succeeded；运行终态仍由核心在资源收尾后裁决。一个本地等待器结束不证明整个 RunScope 已关闭。

连接共享不占用“永远忙碌”的业务资源。浏览器原生下载可在控制释放后继续，但本期不承诺脱离 run 的隐形下载执行器/订阅：需要 path/saveDownload 结果时必须等真实完成；运行结束后不再执行旧 call.log/progress 或后台提交网页动作。公共 handoff 虽存在，本包不为没有公开查询/停止协议的资源自动 handoff；若以后提出独立 browser 后台工作，必须另有明确能力合同和验收，不能由当前文字视为已交付。

## 取消、超时与用户停止

call.signal/deadline 约束本次 I/O：停止接纳本次新动作、移除等待器、发送 cancel_action，尝试停止对应浏览器工作/临时下载。已经发生的网页提交、消息、下载或文件写入不自动回滚。

动作尚未 dispatch 可确认无效果；已 dispatch 且远端未确认停止/完成，保留 effect=unknown 与原关联，不伪造取消成功，也不盲重发。资源真实关闭与网页业务效果分别记录；本地 waiter 关闭不证明网站请求被撤回。控制仍未确认时保留诊断/占用及未结算的 closed，需要重新同步清理事实或显式处理，不能直接释放身份后将旧结果套给新动作。只确认本包 CDP/监听等控制已关闭时，closed 可完成而网页 effect 仍为 unknown；两者不可捆绑为虚假的网页撤回。

`markDeliverable` 只记录实际目标交付提示；`markHandoff` 清理并封闭本 run 对该目标的控制，随后同 run 的写入拒绝，不能借重新 get 绕过。主动 `requestUserTakeover` 先释放目标控制，再用当前 call.requestInput 等待用户，返回只说明收到用户回复；恢复后重新观察并申请新租约，不能拿旧 ref 当作登录完成证据。无原生接管或已关闭/过期的输入请求明确失败。

用户点浏览器原生调试“取消”/接管时，插件发送 detach/user_takeover，结束本 run 的浏览器控制、拒绝该 run 后续写操作并取消等待；当前方法抛 USER_TAKEOVER。扩展不能自行改 run 终态；核心根据 handler 实际结果裁决。脚本可处理失败/交还，不能用同一失效句柄重新接管。浏览器继续运行，已完成结果保留。

## 停用、换版、退出和重启

1. 沿公共协议检查在途调用、固定版本脚本和独立后台业务资源；忙碌则保留原实例/控制入口并报告未生效。空闲共享 WS 连接本身不阻止停用。
2. 核心串行关闭新方法/脚本准入，触发 host.signal，并调用资源停止/dispose。browser 关闭监听、WS、CDP 订阅/本包调试附着和视觉临时状态，不终止用户浏览器。
3. WS 正常关闭给最多 5 秒本地宽限，再终止本包持有的 socket；server 实际 close 且启动已不可能重开后才 resolve closed。公共清理观察先返回 stopping 时如实保留；未确认不发布同名新版或误报卸载完成。
4. 成功后撤下 SDK、脚本、指令、docs/Skills 当前发现；阅读历史按原修订保留。包更新与 Agent 更新分开，不能在 browser 包中修改 Agent 程序、系统服务或重启 Agent。
5. 新版本不能可靠切换 ESM 缓存时，按通用维护返回需要重启和实际版本；不清 require.cache 伪装卸载。需要重启是共同包约束，不增加 browser 专用重启逻辑。
6. Agent 正常退出执行通用运行/资源收尾；异常退出由 OS 关闭监听/socket，浏览器插件重连等待新实例。初始化创建新 boot/generation，旧 run/control 标记中断或失效，保留历史，不重播动作或恢复旧 Promise。

核心只需要执行既定公共加载、实例、方法和资源契约。设计 review/验收必须证明安装/移除本包前后 Agent 启动入口、MCP 工具清单、内部 DDL 和浏览器特例分支均不需要变化；发现真正通用缺口时在公共协议中说明，不能向扩展注入私有 manager。

## 远端租约、断线与闭合证据

每个已登记 RunScope 为目标建立不透明 leaseId，绑定 boot/browserSession/generation/run/target。插件确认租约后才执行其动作；leaseId 不能从脚本指定来替换 call 身份。正常 lease_end 幂等，插件真正撤下本包调试附着、等待器、按键/临时视口和 active 标记后回复 lease_closed。CDP detach 不关闭用户浏览器，也不证明站点提交回滚。

插件在控制 socket 关闭或 60 秒无有效保活后进入本地清理，不能离线继续执行队列。保活来自对应受管实例；Agent 退出/异常崩溃、MV3 worker 重启均要核对自己持有的控制并释放。仅超时或本地 socket.close 不是远端实际清理的证明；未收到证据的 RunScope 保留 stopping/unknown。重连可回报旧 leaseId 的有界清理回执，只用于核对关闭，不恢复旧 run/动作；旧 run 已收到停止请求时不再续约。浏览器已真实重启的新 browserSessionId 使旧原生对象消失，不能只因 worker 重启就假定 debugger 已 detach。

实例停用先对本包所有租约发清理，再关闭本机 server/socket。5 秒 socket 宽限只限制本机等待，不把远端未确认租约标 closed；本机 BrowserService.closed 与 RunScope.closed 分别反映各自实际对象，未确认运行资源按公共停止协议保留。任何清理失败不能使后续新实例悄悄继承旧锁/附着；没有 browser 专用核心清理分支。
