# Nexum Desktop 设计基线

## 产品边界

Nexum Desktop 是独立的、多 Agent 管理客户端。Agent 是唯一一级业务对象，不另建 Device 层。通过 Local 或 SSH 连接管理当前 Agent；既有 AI Host/Cloud→Agent 通道不受影响。用户不需要为了打开 Desktop 强制登录 Cloud。产品能力覆盖 MCP、API、npm、SDK、Skills、Scripts、Instructions、运行活动、日志及 Agent 安装维护。项目、允许目录和访问授权由 Cloud 控制台管理。Desktop 直接连接 Cloud 仅用于浏览器授权配套的一次性授权请求，安装与修复下载由目标机执行。

## 工程与运行

Desktop 位于独立公开源码仓库 NexumAgent 的 `desktop/`，拥有独立 Go Module、pnpm Workspace、依赖锁文件和 GitHub Actions。Wails v3.1.0 管理原生 WebView、窗口、托盘和 Go 绑定；Go 1.26.6 作为后端，React 19、TypeScript 6、Vite 8、Tailwind 4 与官方 shadcn/ui 基础组件作为前端。Go Native Agent 源码、Node Host 和现有 Cloud 发行业务边界不变。没有从私有仓库复制实现或依赖其 Go Module。

## 窗口外壳

macOS 与 Windows 共用 Nexum 自定义背景、字体、标题栏内容及菜单，不采用系统材质背景。主窗口固定为 400 × 680 逻辑单位，禁止调整尺寸、最大化和全屏。macOS 保留 AppKit 原生窗口轮廓、阴影及左上角交通灯，使用透明隐藏式标题栏与全尺寸内容；原生缩放按钮禁用。Windows 采用无边框窗口、主题细边框及右侧最小化、关闭控件，原生轮廓和阴影由平台负责。标题栏 macOS 高度 52px、Windows 高度 44px，使用显式行高和等宽两侧区域，使中央内容保持窗口水平正中央并与窗口控件垂直对齐。不设横向分割线。公共 DesktopTitleBar 在正常工作区和设置页中央显示 Nexum Logo、当前 Agent 名称及下拉箭头，无常驻背景；设置齿轮位于窗口控件另一侧，设置页打开时显示选中状态，再点击返回工作区。启动与客户端更新共用 Bootstrap 界面，标题栏仅保留平台窗口控件，不显示顶部 Logo、页面标题、Agent 切换器或设置按钮。仅非交互区域承担窗口拖动。各业务页标题位于内容区，真实管理连接未验证前只展示选定管理目标，不声称 Agent 已运行；正常就绪控制中心见对应章节。

选择器默认选择本机管理目标，显示「本机」，操作系统主机名仅作为下拉菜单中的辅助说明，不能据此推断已安装或连接 Agent。开发版提供明确标记为示例且未连接的远程环境项，以验证切换交互；生产版不显示预览项。具体切换与远程添加设计见下文「管理环境切换与远程连接」。当前选择仅保存在界面状态；Local/SSH 后端及主应用真实连接入口已接线；Agent 生命周期使用当前已认证目标，开发示例独立隔离。

## 原生系统快捷菜单

macOS 菜单栏与 Windows 托盘单击显示、恢复并聚焦现有主窗口；右键才展开原生菜单。macOS Dock 重开及单实例再次启动复用同一窗口恢复操作，不重载 WebView、重置目标、重连 Agent 或切换页面。保留系统默认 Dock/任务栏功能。

菜单由系统原生绘制、跟随系统外观：顶部为不可点击的真实品牌图标、Profile 应用名与版本；分隔线后依次为「打开主窗口」「设置…」「关于 Nexum」，再分隔后为「退出 Nexum」。菜单项采用原生文字样式，不自绘菜单或模拟系统快捷键。设置和关于复用同一主窗口，分别定位设置顶部及关于标题；原生导航是仅在进程内保存的递增修订快照，事件只作通知，前端读取并拒绝旧修订或未知目的地。打开主窗口不产生导航请求。

右键展开时依据真实 Bootstrap 和已保存语言更新文案及可用性，执行时再次检查状态。非 ready 禁用设置/关于；退出遵循现有 CanQuit，安装/迁移/重启等不可安全退出阶段禁用退出；主窗口仍可显示当前启动/更新页。开发预览不作为真实客户端状态，明确进入设置或关于可结束启动 UI 预览。退出只退出当前 Desktop Profile，不停止 Agent。暂不提供 Agent 状态、启停或环境切换菜单。

## 公共视觉与客户端更新

- 统一采用现有 Nexum Web 产品视觉：浅色画布 #F8FAFC，暗色画布 #141B2D。窗口、标题栏、工作区、更新页及其进度面板使用同一纯色画布，不设顶部色差、分割线或背景光晕。蓝紫品牌渐变仅用于强调版本号与进度；普通菜单沿用共享卡片、边框和文字语义色。
- `frontend/src/theme-palette.json` 是原生窗口初始底色与 React 主题画布的共同来源；`theme.ts` 同步 CSS 和原生窗口，`theme.css` 维护公共主题、品牌与字号/圆角基础，`index.css` 维护公共窗口外壳。Logo 复用公开 Nexum 品牌图标，`components/ui/progress.tsx` 提供可复用且可访问的确定/不确定进度展示。
- 原生系统图标统一以 Desktop 自有的 `frontend/public/nexum-mark.svg`（与 Web 同源的公开品牌标识）为图形源。应用图标使用浅色圆角方形底、透明外部留白和原始蓝色渐变标识；macOS Dock/运行时应用图标使用 1024px PNG，Finder/安装包使用同源多分辨率 ICNS；Windows 任务栏、窗口、系统托盘（浅色和深色）及 NSIS 安装包使用同源多尺寸 ICO。macOS 菜单栏使用 64px 透明背景、单色 alpha 模板，交由 AppKit 自动适配系统外观；不使用 Wails 默认品牌图标。生成资源随独立 Desktop 仓库交付，普通构建校验源图与资源哈希，不依赖私有主仓库或额外渲染依赖。仅重新生成资源时需要原生 macOS 与现有固定 Wails CLI。
- 客户端初始化、检查版本、下载、校验、安装及重启均在同一 BootstrapView 中呈现，沿用已确认的极简启动页。仅更新阶段显示当前/目标版本及实际下载百分比；其他进行中阶段使用不确定进度。失败只提供适用的重试和退出操作；真实强制更新不提供跳过、稍后或进入旧版工作区。
- Desktop 自身更新与 Agent 更新独立，不能停止或修改 Agent；未来 Agent 更新可以复用主题与进度组件，但不复用 Desktop 更新状态或版本身份。
- BootstrapView 以 Go BootstrapSnapshot 为权威状态；仅真实 ready 后开放工作区及开发预览。development Profile 仍只有一个启动流程预览入口和 19 种示例状态；生产版不提供预览入口。示例不联网、不安装、不迁移数据。实际发行检查、签名、下载和安装失败按后端状态展示。
## 客户端启动与初始化

Go 在原生 WindowRuntimeReady 后自动运行单一 Bootstrap 协调器。Windows 创建 WebView 前只准备安全的 Profile 路径；首实例打开日志、取得更新事务锁、校验恢复状态、打开 SQLite 并加载设置。早期路径/原生窗口失败使用系统错误提示；普通存储失败保留窗口显示真实可恢复状态。通知权限不影响启动。

### 职责与顺序

客户端启动只准备 Desktop 自身，不探测或操作 Agent。每次启动仅在首实例进行必要准备；第二实例恢复已有窗口，不重复初始化。

| 阶段 | 责任与就绪条件 |
| --- | --- |
| 应用与实例 | 识别构建版本、平台和 Desktop Profile，完成当前 Profile 单实例判定；不得从 Desktop Profile 推断 Agent 环境。 |
| 本地存储 | 准备 Desktop 专有数据及日志目录，打开或首次创建 SQLite，校验数据库身份、Schema 版本、可读写性。只执行有明确迁移契约且经过验证的迁移，不自动重建未知或损坏的数据库。正常启动不做全库扫描。 |
| 客户端配置 | 读取主题、语言及已有设置；缺失的可选项使用明确默认值，默认本机；真实 Local/SSH 连接列表持久化仍不在此阶段。 |
| 前后端就绪 | Go 发布带 revision 的 BootstrapSnapshot；GetBootstrapState 确认前端已到达绑定。React 监听 bootstrap:changed 并在未就绪时轮询回读，仅接受有效的非旧 revision。 |
| 客户端版本检查 | 在本地客户端就绪后按 Desktop Profile 检查发行通道；未确认有更新且检查因网络不可用失败时允许离线使用，已确认有更新则保持更新限制。命中更新时在同一 BootstrapView 下载、校验、安装及重启，不进入工作区。 |
| 客户端就绪 | 本地准备及版本检查策略允许进入后结束 Bootstrap；当前进入未连接的本机工作区，真实 Agent 环境检查待其后端接入。仅选择目标不代表 Agent 已安装、已连接或已运行。 |

本地准备不以联网、登录 Cloud、安装 Node/npm、发现 MCP/Skills、SSH 探测或系统特殊权限为前置条件。版本检查是后续 Bootstrap 的独立阶段，不将网络检查伪装成初始化步骤；网络中断本身不是 Desktop 初始化失败。

### 状态与失败处理

- `initializing`：界面根据真实初始化阶段提供简短说明，未知耗时显示不确定进度；不计算虚假百分比，不设置人为最短显示时长。
- `checking`、下载、校验、安装与重启：发行构建由 Go 更新引擎提供真实状态。源码/HMR/未配置发行信任的本地候选明确标记 localBuild，不伪造版本检查；只有发行构建使用当前 Profile 的真实公钥检查。若已有签名更新要求，不允许无公钥候选绕过。
- `ready`：本地配置、前端绑定和发行检查策略允许后才开放工作区。Info、设置读写、通知等 Go 服务同时检查准入；Bootstrap 日志入口仅在日志目录可用时开放。RetryBootstrap 只允许后端确认可安全重试的失败；QuitDesktop 和窗口/托盘退出遵循真实关键阶段。
- `failed`：在原启动页展示可理解的失败原因、重试或退出入口；仅在失败阶段可安全重试时才提供重试，避免并发和重复副作用。数据库身份/版本不兼容或损坏时保留原始数据，明确恢复路径，不静默删除、覆盖或降级。日志记录真实阶段及错误，不暴露凭据。若路径准备或 WebView 原生运行失败，使用原生错误提示；启动日志不能创建时先写 stderr，不覆盖或重建用户数据库。

当前实现覆盖 Bootstrap、版本检查、签名验证、下载、安装辅助进程及事务恢复。真实 Agent 环境检测与生命周期独立开发；连接持久化已实现后端。Windows 原生更新、平台签名正式发行和公开 Release 下载需独立真机/CI 验收。

### 启动页视觉

采用已确认的 400 × 680 启动页布局：统一主题画布，原生窗口控制，不显示顶部 Logo、页面标题、Agent 下拉或设置。主体仅保留居中 Nexum 纯文字字标、约 58 × 3px 不确定加载细线、简短状态文案与底部 DESKTOP。使用现有公共主题色和进度组件，细线使用中性色，避免页面背景与原生窗口色差。浅/深色与简体中文/English 沿用客户端设置，减少动态效果偏好下停止动画；失败以同一布局呈现。同一布局还用于检查与更新的状态。统一开发预览保留初始化文案及结束预览入口，所有阶段均可通过底部仅开发版可见的阶段选择器切换；正式界面及公共 CSS 不变。所有预览都不执行额外初始化、数据备份/迁移/恢复、网络更新或安装，不自动成功；正式版不提供预览控制。

Bootstrap UI 展示阶段：初始化（目录准备、本地数据检查、配置加载、系统服务准备）、检查更新、下载、校验、准备安装、重启、数据备份、数据迁移、数据校验、升级恢复；失败分别为初始化、下载、可信校验、数据迁移、数据版本不兼容、安装权限不足。19 种状态共用原有字标与固定中心锚点、58 × 3px 进度槽及底部 DESKTOP。仅下载显示真实百分比（未知为不确定进度），版本信息仅在客户端更新阶段显示。失败用公共主题错误图标、对应主操作、可用时打开客户端日志及退出。数据迁移仅在后端明确可安全重试时提供重试。权限不足的手动安装按钮在开发预览中明确反馈未安装，真实操作由后端校验并在文件管理器显示已验证的安装包，用户手动安装，不盲目启动第二个安装器。预览重试只切换对应示例，不执行副作用。备份、迁移、安装及重启等关键阶段不额外提供正文退出按钮；系统窗口控制、退出及强制更新门禁由 Go 后端负责。

## 客户端更新与恢复

发行来源固定为公开仓库 bYiyLi/NexumAgent 的 GitHub Releases。逐页检查 desktop/v*，排除草稿、另一 Profile 与其他发行类型；SemVer 比较禁止降级。生产稳定版和开发预发行版使用不同的内置 Ed25519 公钥。发行构建缺少信任配置时阻止启动；普通本地候选不参与发行更新。清单原始 JSON 与独立 Base64 签名验证通过才确认新版本，严格校验格式版本、App ID、Profile、语义版本、四平台制品名、长度、包及安装后程序 SHA-256。HTTPS 固定 GitHub 源及允许的重定向主机，不接受 WebView 提供下载 URL、目标路径或命令。

更新工作目录为 Profile 数据根的 updates/（state.json、downloads/、staging/、install.lock）。state.json 使用原子替换与签名清单保存最高已确认要求及安装事务；未发现可信更新且网络不可用时允许离线；已知要求持久化后断网、退出、重启仍必须满足该版本。签名/协议异常停止，不用未验证的清单解除门禁。完整包流式下载，按实际字节数更新状态；下载失败清理本次临时文件，只复用大小和哈希都验证通过的缓存。

安装辅助进程从隔离事务目录运行同版本可执行文件，在核对事务、已安装源程序、清单、平台制品和签名后取得跨进程安装锁并确认等待旧进程；旧客户端只在收到交接回执后正常退出。macOS 只读挂载 DMG、验证应用 ID、程序哈希、codesign；生产另验证原 Developer ID Team 及 Gatekeeper 策略。将新版 app 暂存在同文件系统，用原子 RENAME_SWAP 交换，旧 app 保留为备份。Windows 仅支持现有固定 per-user Profile 安装路径；生产核对 Authenticode 受信状态和同发行者，运行 /S NSIS 安装器，等待实际退出并核对新程序哈希，保留旧程序备份。不绕过系统权限、不覆盖其他 Profile、不碰 Agent。下载/签名/安装失败保留更新要求，日志记录真实原因；安装权限不足或 Windows 安装结果未知时显示手动安装入口，定位已验证的包，不自动重放未知副作用。

辅助进程记录安装状态后释放锁并重新启动客户端。新版重新读取事务，核对真实安装程序及本地数据；前端绑定确认及本地初始化成功后确认该次安装，之后仍按版本策略决定准入。已确认事务清理下载、辅助进程与该次程序备份，保留安装日志及签名版本下限。若新程序未能完成启动，保留更新事务和原程序/迁移前一致备份；能证明原程序未替换的中断可重试，不能证明安全恢复条件的安装/迁移异常停止并保留现场，当前不自动覆盖不确定状态下的数据库或回退已安装新版。迁移事务失败自动回滚数据。手动回到旧程序也不能解除签名更新要求。macOS 既往原生验收用隔离应用、临时签名和合成 Schema 2 验证真实升级链路；当前脚本已改为真实 Schema 1→2；Windows 原生与正式签名发行仍需验收。

## 管理环境切换与远程连接

### 产品交互

Desktop 完成 Bootstrap 后直接进入本机，不增加环境选择向导。标题栏中心的 Logo、当前环境名称与下拉箭头保持原位；该入口切换的是 Agent 所在的管理环境，而非已安装 Agent 的列表。Local 固定保留，不可删除；远程环境在真实连接成功后使用获取到的非空远程主机名（Hostname）作为名称，获取失败或为空则回退到主机地址；未来支持重命名、编辑连接配置、移除。名称只用于显示，不作为管理目标的唯一身份。切换管理目标不停止或修改原目标 Agent，不影响客户端设置。新目标的读写操作必须使用其独立连接身份，不接受过期检测结果或原目标的初始化授权。

采用 400 × 680 高保真比例：菜单居中于现有触发器下方，宽约 304px，采用本地、远程分组、设备图标、名称及主机说明、当前选中勾选、SSH 连接状态，末尾「添加远程环境」。连接状态仅表达 SSH 会话，不能推断 Agent 是否安装或健康。添加页复用标题栏和公共主题：左右边距 24px，左对齐标题和说明，主机地址和端口（同行，端口默认 22）、用户名、认证方式及动态认证字段，不提供环境名称输入框，输入高度约 40px，底部首次连接信任提示、46px 主按钮「连接并添加」与「取消」。新建远程环境默认采用密码认证，直接展示空白、默认隐藏且可切换显示的密码输入框，不额外弹出输入页。认证方式依次显示「密码认证」「使用本机 SSH 密钥」「指定私钥文件」；本机 SSH 密钥通过系统 SSH Agent 使用已加载的密钥，指定私钥时展示文件选择。返回配置时保留本次所选认证方式，不保留密码。提供键盘可用的菜单和输入、可见焦点、浅深色与中英文支持。取消或切换目标时丢弃未提交的表单；设置仍为应用级页面。

### 连接契约

- Local 与 SSH 通过统一管理环境访问抽象供 Agent 业务使用，SSH 先建立经过认证的目标会话，再进入与 Local 相同的只读环境检测、必要时初始化授权、初始化执行及连接验证流程。检查结果确定后分流到初始化、配置、升级、修复、启动或工作区；已健康环境直接进入工作区，不重新安装。
- 新远程连接应先校验地址、端口、登录身份与认证方式；首次连接必须展示可验证的主机身份/公钥指纹并取得明确确认，已知主机密钥变化需阻断并单独处理，不能自动信任。认证方法包括本机 SSH Agent、用户选择的私钥和密码；实际密钥选择、加密私钥口令、本机 SSH Agent 及信任库契约见下文。先验证主机身份再发送认证秘密；默认不保存密码。
- 只有连接与身份验证成功后才保存非秘密连接元数据并切换至该环境。凭据、私钥及口令不得持久化到普通 SQLite、日志或 WebView 存储，不跨页面保留密码；记住凭据需用户显式选择并使用系统凭据存储。连接失败保留原环境及可理解的错误与重试，不能伪造已连接、Agent 未安装或初始化成功。移除连接配置不卸载或停止远程 Agent。
- 实际连接、主机认证和持久化已有 Go 实现，主应用真实连接入口已接线。以下仅说明独立 UI 预览：development Profile 下可选择明确标注的远程示例（均为未连接，地址使用文档示例地址），通过同一个环境确认页预览后续流程；添加表单可编辑非秘密示例字段并进行基本输入校验，密码字段只用于本地示例交互（明确提示勿输入真实密码），私钥选择仅展示示例，不读取真实文件。提交进入显式标注的连接状态预览，不联网、不新增目标、不执行 Agent 操作，不保存密码或私钥。取消连接或返回修改保留非秘密表单内容，密码与示例密钥选择重置；取消表单、选择其他目标或进入设置退出连接预览并丢弃草稿。正式版使用实际 Local/SSH 入口，不展示虚假远程项或任何开发预览。

### Environment Runtime 统一契约

- `internal/environment` 是 Go 业务层的目标访问契约，提供 Identity/Alive、Run、Getenv、Join、Stat、ReadDir、MkdirAll、ReadFile、WriteFile、Upload、Download 和 Close。Local 使用本机原生接口；SSH 使用受验证的 SSH 会话和 SFTP。应用不要求远端 Agent 已安装。第一阶段仅探测系统、架构、主机名、登录身份及 home，不读取 Agent 私有配置。
- 命令使用独立 Program/Args、工作目录、环境变量与 stdin；结果区分启动状态、真实退出码、OutcomeKnown 及输出截断。Windows 采用目标系统的路径及参数处理；第一阶段支持绝对盘符路径，不承诺 UNC。命令取消可能使远端结果未知，关闭连接而不是断言远端进程已终止；不自动重放。文件写入先暂存再替换，SFTP 无安全替换能力时拒绝覆盖。读取有界。SSH keepalive 负责发现断线。
- 本机固定身份 local；远端以独立 ID 和规范化 host/port/username 唯一定位。主机信任按 host/port 固定公钥指纹，不因移除环境或更换用户名自动清除。首次握手确认真实指纹后才认证；变化阻断，不静默覆盖。主机信任和连接元数据在连接、身份探测及 SFTP 成功后事务保存。
- 密码、指定私钥（含加密私钥口令）和本机 SSH Agent 三种认证。记住凭据默认关闭；显式同意后使用按应用 Profile 隔离的 macOS Keychain 或 Windows Credential Manager；SQLite 只保存引用，不保存秘密。原生私钥选择器只向 WebView 返回文件名和临时 token。Wails 持久日志不记录绑定参数。
- Manager 管理连接、尝试 ID、状态、取消及关闭；过期或已取消尝试不能自动重新建立连接。Wails 服务只公开环境配置与连接流程，不向前端开放通用命令或文件读写。上层 Agent 检测、安装和维护均独立于本阶段。
- Go Runtime、环境服务、Schema 2 及真实模式 UI 已接线。开发预览表单与真实连接分离；真实连接由原生凭据存储及主机身份校验保护。验收与剩余任务见 [环境运行层 Phase](../development/desktop-environment-runtime.md)。

## Agent 环境检查

### 职责与触发

Desktop 自身 Bootstrap 完成后进入本机管理目标；用户切换到其他本机/已认证 SSH 目标时，从同一环境检查入口识别该目标。Local/SSH 仅为目标访问适配方式，不复制检查规则。首次 SSH 必须完成主机身份验证和用户认证后才允许检查，未连接不能视为未安装。

Desktop 管理 Agent 的基础安装、配置、服务及版本；Agent 自主管理内部运行环境。检查必须能够在 Agent 未运行时执行。检查过程只读、可取消、有界，不能安装、升级、启动/停止 Agent、创建目录、修改配置或迁移数据。所有结果绑定当前连接身份、目标用户、Profile 和检查批次；切换目标、连接断开或取消时丢弃旧批次，不能用其他目标的结果执行操作。

### 检查范围

| 检查项 | 所需事实 |
| --- | --- |
| 系统信息 | Hostname、OS 及版本、CPU 架构、当前操作用户和主目录 |
| 系统条件 | 是否支持目标平台、安装空间是否满足要求、必要路径及操作权限（无法只读确认则标为未知） |
| Agent 根目录 | 按目标用户和指定 Profile 解析真实路径；检查存在性、目录类型、所有权及有效访问权限，不跟随未经验证的重定向 |
| Agent 程序 | 是否确实安装、可执行目标及平台、实际版本、与 Profile 的归属关系 |
| 基础配置 | 受限查询确认连接配置是否存在、可解析，Server URL 是否符合当前 Profile、Token 是否存在或已确认失效；不向 WebView 返回 Token 或完整配置 |
| 系统服务 | 对应目标用户和 Profile 的服务注册、启动目标及配置、运行状态；运行进程不代表管理连接就绪 |
| 版本兼容性 | 目标 Agent 与管理协议的版本兼容性及可用更新；不可获得版本策略时不得伪造最新版本 |

根目录遵循已存在的 Agent 安装约定（production 为目标用户的 ~/.nexum，development 为 ~/.nexum-dev），不得把 Desktop 自己的数据目录、连接对象名称或本机当前工作目录当作远端 Agent 根。Desktop 与 Agent 的 Profile 不得静默互相兜底。正式探测接口及授权还需明确设计；当前工程约束仍禁止直接读取或写入 Agent 私有 Profile 数据/SQLite。未来使用明确允许的安装元数据/受限状态查询，由拥有该数据的组件返回最小脱敏结果；不在 Desktop 复制 Agent 内部解析器。检查只读权限事实，不以实际写入探测文件确认权限。

受管 Node.js、Node Host、npm/pnpm、SQLite 初始化/迁移、依赖恢复、扩展及 Agent 内部数据均由 Agent 自身维护；Desktop 基础安装检查不直接读写 Agent 私有状态。Native inspect/observe 可选择 --runtime-progress，通过绑定 Profile、Cloud origin、Agent ID、Boot ID 的只读管理请求获取 Node 检查/下载/安装、pnpm 准备、Host 检查/下载/启动/配置/重试/失败与自升级实际进度。旧版拒绝可选参数时只回退只读事实查询，不能重放任何操作。只有已验证管理连接和同一运行身份才进入工作区；已知 Runtime 准备最多等待 10 分钟，失败、未知或不支持进度的旧版且执行未就绪时允许降级管理，不误报执行能力可用。

### 结果分流

每个检查项独立记录已确认、缺失、不兼容、异常、不适用或未知，以及不含秘密的错误原因。检查失败、权限拒绝、身份不匹配或策略未知时不得猜测安装状态。只对已有确切事实判断下一步；同时存在多个缺陷时先阻止不安全操作，修复前重新验证目标和最新快照，不以旧检查结果授权修改。

| 检查结果 | 下一步 |
| --- | --- |
| 明确未安装且满足初始化条件 | 初始化授权（不自动安装） |
| 已安装且程序健康、Token 明确缺失或已确认失效 | 显示「Agent 未授权」，复用「连接 Nexum Agent」授权流程恢复连接，不重新安装；更新凭据仅在明确授权并成功兑换后执行 |
| 版本不兼容或强制升级 | 观察 Agent 自升级并验证恢复；未运行时经独立启动流程处理 |
| 已有基础安装损坏、目录/服务异常、配置损坏或 Server URL/Profile 不匹配 | 修复确认，不删除用户数据；不能仅据配置异常判定未授权或自动切换 Profile |
| 网络连接失败、授权状态未确认 | 显示网络异常及重新检查，不自动重新授权、重置 Token 或安装 |
| 安装与配置正常但未运行 | 启动 Agent，实际启动前核对目标与权限，并验证管理连接 |
| 已运行、基础环境及管理连接正常 | 直接进入工作区；兼容版本存在可选更新时允许进入并提示 |
| 不支持、权限不足、检查失败或结果未知 | 显示原因、重新检查或退出，不进入安装、升级、修复或就绪状态 |

初始化、配置、修复和启动由独立操作流程消费检查事实并执行必要确认；升级由 Agent 自身执行，Desktop 仅观察与验证；真实管理接口未就绪时不能报告正常可用。版本策略、真实管理协议、受限探测及操作接口另行设计。Agent 内部自举状态不由 Desktop 代为修复。

### 页面及预览

沿用 BootstrapView 的 400 × 680 统一画布及 Nexum 居中字标，保留当前目标公共标题栏、浅深色、中英文

development Profile 提供唯一的「Agent 生命周期预览」入口（--preview-agent-lifecycle / pnpm preview:agent-lifecycle），旧检查、初始化、启动、升级和修复参数作为兼容别名进入同一真实渲染器的无副作用示例。

## Agent 初始化授权与执行

### 用户路径

- 消费当前目标、Profile 与检查批次的环境事实；明确未安装且满足基础条件，或已安装健康 Agent 的凭据明确缺失/失效时，直接进入「连接 Nexum Agent」。首次安装与连接恢复复用授权页，仅文案和执行计划不同；配置损坏、Profile 不匹配或网络失败不自动归为未授权。不再单独显示机器信息确认页，不要求用户输入 Server URL、Token、安装目录或 Node 版本。已健康且管理连接可用的环境直接进入工作区。
- 构建 Profile 对应内置 Nexum Cloud origin；不得从输入、跳转、远端主机名或旧配置回退到另一环境。Go 后端在获得实际检查结果后固定目标、用户、Profile 与计划。用户在系统浏览器的 Console 初始化授权弹窗创建或选择 Agent，并明确同意本次计划。
- 等待授权期间可重新打开原仍有效请求或取消；拒绝、超时与不确定结果独立处理。回调成功不代表安装已完成。只有一次性授权码交换成功、目标身份和检查前置条件仍成立，才进入真实执行。切换目标、授权作废或计划变化重新检查并发起新授权，不复用旧结果。
- 首次安装示例依次展示：准备安装目录与权限、下载 Agent、校验安装包、安装与配置、注册系统服务、启动 Agent、验证 Agent 连接。已有健康 Agent 的连接恢复示例仅展示确认现有 Agent、恢复连接配置、必要时启动或重启、验证 Agent 连接，不下载、不校验安装包、不重新注册正常服务。实际执行计划由 Go 根据当前检查事实与授权确定，跳过不必要步骤；不得从前端预览推断实际操作。真实进度由操作事实驱动；只有已知真实字节总量时才能显示下载百分比。完成必须核对实际运行身份与选中 Agent ID 及管理连接；Agent 内部运行时和扩展仍由 Agent 自身管理。失败不自动重装、重置凭据、卸载或清理数据，先重新检查实际影响。

### Cloud 接入契约

Cloud 的完整规范与真实服务实现由 Nexum 主仓库 `docs/design/desktop-install-authorization.md` 负责。下列是 Desktop 真实实现遵守的接线边界：

1. Go 使用当前构建环境内置 Cloud origin；为目标批次生成随机 state（32-byte Base64url，无 padding）及高熵 PKCE verifier（43–128 字符），S256 challenge（32-byte Base64url）。监听本机 IPv4 loopback 127.0.0.1 动态高位端口，固定回调路径 `/nexum/desktop/callback`；SSH 目标仍由本机接收回调。
2. POST /api/desktop-install/start 提交 purpose（initialize/restore）、restore 可选的 expectedAgentId、profile、hostname、platform、arch、connection、redirectUri、state、codeChallenge；返回 requestId、authorizationUrl、expiresAt。Cloud 固定授权目的和已知 Agent 身份；原生后端核对授权 URL 属于固定 Cloud origin 后才打开系统浏览器。请求有效 10 分钟；回调 code 最长 2 分钟且不超过请求期限。
3. Cloud 通过已有 Browser Session 认证账户，Console 按 purpose 展示授权：initialize 可创建或选择符合条件的 Agent；restore 禁止创建，只能选择已有 Agent。若 Desktop 已知原 Agent ID，Cloud 返回该绑定并在决策前校验所选 ID，Web 仅显示该 Agent；身份未知时明确警告用户核对主机与平台。restore 的 ID 不匹配在 Token 轮换前拒绝。已有 Agent 授权明确说明兑换时轮换 Token、断开旧连接及可能中断任务；批准不执行轮换。
4. `POST /api/desktop-install/exchange` 提交 requestId、code、codeVerifier、redirectUri，得到 agentId、agentName、token、profile。Cloud 事务内复核权益与凭据，原子消费授权码；新建在兑换时创建，已有 Agent 在兑换时自动重置 Token 并关闭旧 WSS，保留 ID、名称和 Cloud MCP 授权关系。其他授权已轮换凭据时返回 409 desktop_install_credential_changed，重新授权；不自动重复兑换。正常 SSH/WSS 重连不轮换。原生端不带 Browser Cookie/Origin/Sec-Fetch-Site；Token 仅在 Go 与受保护安装输入中短暂使用，绝不能进入 WebView、普通日志、URL、命令参数或环境变量。Desktop 通过受保护的标准输入交付凭据；Cloud 安装器提供专用 Desktop stdin 模式，已安装 Agent 由 Native helper 恢复配置，不可绕过 Agent Profile 私有数据边界。
5. `POST /api/desktop-install/cancel` 以 requestId 和 codeVerifier 取消未消费请求；若已消费，按实际注册/安装状态恢复，不能假定取消回滚了结果。浏览器回调、网络断开或 RPC 超时后先确认真实状态；禁止自动再次创建 Agent。
6. Go/Wails 已由 Lifecycle Controller 接入真实 Local/SSH 目标，状态快照携带 operation ID、revision、target identity、check revision、phase、safe error 与 retryability。Go 主动检查并维护权威状态；前端订阅/读取并丢弃过期、倒序或其他目标结果。写操作前重新检查目标和事实；未消费授权可取消，已发生的副作用必须先查证，不自动重放。

### UI 实现

授权引导、等待、拒绝、过期、安装、启动和恢复均复用统一 Nexum 字标、真实目标、状态文案和底部适用操作；可展开实际观察阶段。仅在字节总量可信时显示真实百分比和已下载量；其他等待采用不确定进度。未知/失败不自动重放操作，成功由 Go 验证后进入工作区。

系统浏览器回调页使用带 Nexum Logo 的居中状态卡片，语言取发起授权时的 Desktop 界面语言，配色跟随浏览器的浅色或深色偏好。收到批准时显示「已收到授权」，提示返回 Desktop 查看进度。拒绝回调显示「本次授权未完成」，提示回到 Desktop 选择「重新检查」后再次授权。两种结果均提示可以关闭标签页，页面样式和图标随 Desktop 内嵌交付。

初始化和连接恢复均由统一生命周期预览覆盖；保留 --preview-environment / pnpm preview:environment 作为旧入口别名。真实操作与预览分离，不从示例阶段推断实际执行计划。


## Agent 自升级状态观察

### 职责和触发

Desktop 不拥有 Agent 升级器，不新增升级确认、下载/校验/替换程序、升级任务调度、强制停止或 Token 重置逻辑。Agent 继续按 Nexum 主仓库 `docs/design/agent-runtime.md` §18.1.3 及 `docs/design/deployment-configuration.md` §11 自升级：Cloud 426 触发强制升级；健康连接上的 Native 版本轮询（当前实现每 5 分钟）在任务及收尾完成后暂停新任务准入并升级。macOS/Linux 原子替换并由原服务重启；Windows 使用当前 Profile 一次性 Upgrade 任务。不把 Desktop 自身强制更新与 Agent 更新混用。

- 环境检查确认当前版本必须升级：进入被动等待页，无需再次授权或点击升级。Agent 已运行时仅观察；若安装与配置正常而未运行，通过独立启动流程让 Agent 自己检测版本，不在环境检查或观察页隐式启动。
- 当前版本兼容且管理连接仍可用时允许进入/留在工作区；可选升级等待期间只提示状态。实际升级造成管理连接暂时不可用且有可靠证据时，显示相同升级状态页；验证恢复后返回原目标的原工作区页面。
- 返回、切换环境、打开设置、隐藏或退出 Desktop 只停止/暂停当前 UI 观察，不取消 Agent 的自升级或停止其服务。再次进入需重新检查实际状态，旧观察结果不能影响新目标。
- 升级不重新绑定 Agent、不重置 Token；不自动卸载、回滚、清除配置或用户数据。Agent 负责自己的 Schema 迁移与运行时恢复；具体版本的数据迁移/保留语义遵循其发布契约，不承诺保留所有不兼容历史记录。

### 状态及后续只读契约

以下为生命周期业务状态，具体的 Native v1 事实契约及实现边界见下文：

| 状态 | 证据与行为 |
| --- | --- |
| waiting | 已核实目标版本必须升级或 Agent 确认待升级，尚无执行证据。允许等待原任务收尾；不声称已经下载或替换。 |
| upgrading | 已确认当前目标/用户/Profile 的 Agent 自升级实际在执行；有真实下载总量时显示确定进度，否则显示不确定进度；观察有界。 |
| reconnecting | 已确认新进程及实际版本，正在验证管理连接和身份，不因二进制替换或 Windows 辅助任务已接纳即报告成功。 |
| unknown | 超时、SSH 断开、状态缺失/过时、旧 Agent 不支持状态接口等导致无法确认结果；重新检查，不能直接判定失败或重装。 |
| failed | 有可信失败证据且未处于正常重试/恢复过程；进入重新检查及独立修复流程。仍在 Agent 正常退避重试时保留观察状态及安全说明。 |
| ready | 重新检查确认当前运行版本满足有效 Cloud/管理协议策略、目标/Profile/Agent 身份与真实管理连接均匹配；直接进入（或恢复）工作区，无单独成功页。 |

Agent 自升级的完整跨重启步骤仍由 Agent/其一次性升级执行器拥有。Desktop 当前通过 Native v1 读取实际运行版本、Profile、Agent 身份和管理连接，并观察升级前后版本变化；agent-readiness.json 仍只表达有限就绪事实，不能据此推断下载、替换等全部步骤。未来若需展示更细的 Agent 自升级阶段，须由 Agent 提供独立、脱敏、可跨重启读取的状态契约；不得读取私有 SQLite、完整 config.json、任意日志或 Token。

### UI 与开发预览

升级复用统一生命周期画布，显示 Nexum 字标、实际目标和版本；等待升级与真实升级区分。Native 提供字节量时显示确定进度，其余使用不确定进度。失败或未知先重新检查，无手动执行或取消自升级按钮。

升级示例归入统一生命周期预览，旧 --preview-agent-upgrade 参数仅作兼容入口；正式模式仅观察 Agent 自己的升级。

## Agent 异常修复

### 职责与准入

Desktop 仅管理基础安装、可执行程序、安装目录及系统服务、必要连接配置的已确认异常；继续通过 Local/SSH 统一目标访问层使用受限操作，不直接读写 Agent 私有 Profile 数据或 SQLite。Agent 自主管理 Node Host、npm、SDK、MCP、Skills、Scripts、Instructions、内部数据库、日志和运行时恢复。未安装进入初始化、凭据明确缺失/失效进入连接恢复、仅版本不兼容进入升级观察、仅未运行进入启动；网络/身份/权限不足或无法确认状态先重新检查，不从未知事实推导损坏。不能安全修复时阻断并说明原因。

真实环境检查确认异常后，依据当前目标身份、操作用户、Profile、检查 revision 与实际异常生成最小修复计划。展示可安全恢复的具体问题、预期变更、必要权限及是否停止/重启或中断在途任务；由用户明确确认计划后执行。计划发生变化必须重新检查及确认，不能用旧确认授权另一目标或更大变更。不同异常可对应以下计划（不是固定全量安装流程）：

| 确认的异常 | 修复边界 |
| --- | --- |
| 固定 Native 程序缺失 | 仅在 Profile、目录、配置、凭据和服务归属可验证时，按 Cloud Manifest 获取匹配平台制品并校验版本、大小和 SHA-256；Native helper 仅补齐确认缺失的文件，不覆盖已有或损坏程序。 |
| 安装目录/必要权限异常 | 验证真实路径、目录类型、所有者和目标权限，仅修复确有依据的路径与权限；拒绝未经验证的链接、递归权限放宽或删除数据 |
| 系统服务注册/配置异常 | 恢复当前目标用户与 Profile 的必要服务定义；不修改其他服务 |
| 基础连接配置无效/缺失 | 仅通过浏览器 restore 授权；已知 Agent ID 绑定并由 Cloud 在轮换前校验，服务安全停止后由 Native 原子更新并回读。未知格式或身份冲突阻断。 |

保留现有 Agent 身份、有效凭据、用户配置及数据；不自动重装、卸载、清空、重置 Token、修改不相关权限或修复内部扩展。修复可能需要停止/启动/重启服务，先检查运行任务及权限并说明影响；不能保证安全停机时禁止盲目强停。验证实际修复效果及身份、版本、管理连接，再执行新的环境检查。正常就绪由环境检查分流，不增加修复成功确认页。

### 状态及操作契约

当前真实修复入口由 Lifecycle Controller 和 Native CLI v1 提供；修复计划与操作绑定当前目标、Profile、检查 revision 和 operation ID。

### UI 与开发预览

定向修复复用统一生命周期画布；确认状态显示已验证异常、修复范围和操作影响，底部提供适用确认与重新检查。执行过程可展开观察阶段，不能将已观察阶段直接视为完成。未知结果先复检。

修复示例归入统一生命周期预览；真实运行路径仅对已确认缺失的固定 Native 程序/服务提供定向修复，其他损坏或归属未知时阻断。

### 真实数据与状态边界

只有当前目标经过实际环境检查、Agent 身份与 Profile 匹配、基础生命周期就绪及管理连接验证后才进入真实控制中心。运行健康、Desktop→Agent 管理连接、Agent→Cloud 连接分别由权威状态返回，不能从进程、SSH 会话、其他连接或前端计时器推断。正常页面使用真实 Agent 名称（未获得名称时使用已核实的主机身份）、运行版本、OS/arch；未知值明确标注。健康状态与两条连接状态独立显示，不把 Cloud 离线当成 Agent 已停止或自动要求重新授权。兼容版本、管理连接仍可用时允许在本地管理已有能力；Cloud 依赖业务按实际可用性单独限制。管理连接丢失时停止写操作，重新检查实际状态；已证实升级进入既有升级观察，已证实异常进入既有诊断/修复，未知结果不得触发重装或 Token Reset。实时状态/查询需绑定目标、用户、Profile、Agent 身份及检查/连接修订，丢弃过时或其他环境结果。不得读取 Agent 私有 SQLite、完整配置或凭据替代受限管理接口。

Cloud 连接状态同时核对本地管理通道的连接事实与 Cloud 已登记的同一 Agent、Profile 和 Boot ID；Desktop 通过受限 Native 只读命令检查，每次结束后间隔 5 秒再次检查，最长保留 12 秒内的结果。检查失败、过期或旧协议不支持时显示未知。Cloud 已断开但 Agent 尚未发现半开连接时，按 Cloud 的事实显示离线；本地已发现断开时立即显示离线。该检查不改变 Agent 心跳、连接或任务执行，凭据不离开 Native 受限边界。

development Profile 的工作区预览保持独立。Agent 设置与维护在真实工作区内使用当前已验证的 Agent。

### AI 资料清单

沿用能力管理的二级页面结构，Skills、Scripts、Instructions 混合排列，保留返回和市场入口；列表无重复标题、说明、分类、搜索、外层卡片或分割线。条目展示类型、名称和简短描述或来源，点击查看对应资料；Skill 显示使用时机和随附文件，Script 显示使用时机、输入和输出，Instruction 显示适用范围与正文。资料正文只读，返回时恢复原列表位置和焦点；中英文、浅深主题沿用 Desktop 设置。

允许单独删除的个人 Skill 或 Agent 本地 Script 在详情右上角提供「删除」，确认弹窗标明名称、实际位置和不可撤销的影响；共享个人 Skill 额外提示其他使用该目录的 AI 工具可能受影响。内置资料和扩展提供的资料不提供单项删除，详情说明由 Agent 或所属扩展维护。真实动作必须先确认来源、目标和授权，再通过受限管理接口执行；来源或权限无法确认时不提供删除入口。

预览中的条目及详情均为示例；删除确认仅从预览清单移除条目。真实工作区通过已验证的本机或 SSH 目标以及同用户 Native 管理端点读取 Agent 级资料，复用现有资料发现与读取校验。清单包括当前系统用户的个人资料、登记的本地 Scripts、已核实的内置资料和当前已批准的扩展资料。Project 级资料与需要 Cloud 用户授权的 MCP/API 派生资料仍由控制台管理。

### AI 资料后台检查

Desktop 的 Go 后台拥有检查调度、上游版本比对与状态汇总。目标管理连接就绪且 Agent 与 Cloud 连通后立即读取资料清单，随后每 60 秒读取一次；一次只运行一轮，窗口隐藏到托盘时继续，退出或切换目标时取消。Agent 同用户管理端点只按需返回资料来源、修订、现有加载诊断及删除资格，不新增 Agent 定时任务或执行技能和脚本。

Desktop 每 6 小时检查可核实的公开 GitHub 技能修订。目标上的短时 Native CLI 读取当前用户 [skills 安装锁](https://github.com/vercel-labs/skills/blob/main/src/skill-lock.ts)，核对实际已安装目录的 Git tree 摘要与锁记录，Desktop 按仓库和目录查询 [GitHub Trees API](https://docs.github.com/en/rest/git/trees)；来源、目录或摘要不能确认时显示更新状态未知。只传递公开仓库和 ref，不上传本机路径或文件正文。失联、旧版协议、限流和检查失败不作为正常或危险的证据。

「AI 资料」卡片右上角按危险、建议、更新的优先级显示一项提示。可确认的 Skill 入口缺失或加载格式错误、Script 头部或 Schema 被加载器拒绝为危险；经核实的上游仓库归档为建议；有更新时显示待更新技能数。清单展示各条提示，详情展示原因或修订，未知不显示危险角标。Cloud 掉线时，Desktop 的资料清单、详情、巡检和删除确认均暂停，恢复后重新读取。Native 通用管理端点的离线只读能力不改变 Desktop 资料流程的在线门禁。

个人 Skill 与 Agent 本地 Script 的删除由目标 Agent 的同用户管理端点完成。准备阶段重新解析当前资料身份，返回用户可见的实际位置和两分钟有效的一次性确认凭证；确认阶段复核 Profile、Agent 与 Boot、来源、文件身份及内容修订，拒绝路径链接、越界或变化的对象。执行后回读目标；断线或响应丢失导致结果未知时先重新查询，不能自动重试删除。内置和扩展资料不提供单项删除。

### Agent 设置与维护

展示实际设备、Agent 版本、平台、Profile、系统服务、管理连接、Cloud 及执行状态。资源用量是当前 Agent 的受管 Node Host 实测 CPU 和 RSS，显示采样时间并可刷新；单次读取失败或进程退出时显示不可用。系统事件通过 Native 读取当前 Agent 最近 20 条脱敏事件，只返回固定类别、组件和时间，可复制诊断摘要；空日志、采样失败和管理断开分别显示。页面内以留白分组，不使用分割线。

维护操作由 Desktop 编排，确认框展示设备、Profile 和影响。请求绑定当前 Local/SSH 目标、Profile、生命周期检查修订、Agent ID 和 Boot ID，目标切换后丢弃旧响应。旧版 Native 或管理连接不可用时不提供操作；真实进度与已确认结果分别展示，中途断线或回执丢失先重新检查，结果未知时不得自动重放。服务归属、运行中的任务和已受理的包维护无法确认安全时拒绝停机；Agent 仅为此提供最小的身份及准入保护接口，维护、启动和自动升级共用同 Profile 安装锁。

重启须确认旧实例退出并验证同一 Agent ID、新 Boot ID；停止须确认服务停止且管理连接消失，再进入既有启动流程。现有启动流程需要 Cloud 验证保存的凭据，因此 Cloud 离线时禁止重启并说明原因；停止确认同时说明重新启动依赖 Cloud。重新安装覆盖当前 Profile 的 Native、官方 Node.js/npm、固定 pnpm 与 Cloud 指定版本的 Node Host。先下载验证 Native，再由已校验的目标助手在独立私有暂存槽重新准备官方运行时（不复用已有安装目录、不碰用户扩展树），取得同 Profile 安装锁后再次核对发布版本、保存凭据、当前 Agent/Boot 身份和目标目录，安全停机后替换官方运行资源与 Native。系统服务定义保持原样，复用已验证注册并恢复启动；保留 Agent ID、Token、配置、用户 npm 声明/锁文件/扩展、AI 资料及 SQLite 历史，不重新浏览器授权。已知阶段和真实下载字节复用统一生命周期画布；初次资源准备失败不发出停机请求。只有已确认 Host 监督、Run 收尾和包维护全部静止时才允许未就绪 Agent 安全停机；包修改仍要求健康 Host。替换失败在确认未启动新实例、Native 未改变时恢复已移动的官方目录；无法确认结果保留私有恢复槽，阻止覆盖和自动重放。新 Desktop 显式要求 full-runtime 受限命令，旧助手不支持时不得退回 Native-only 重装。启动受理后重新核对同一 Agent、新 Boot ID、目标版本及 Node 执行就绪，异常按降级/未知状态处理，不盲目回滚已启动实例。重置连接复用绑定原 Agent 的浏览器 restore 授权，在批准后再次确认目标和空闲状态，安全停机后才兑换，通过受限标准输入交付凭据；取消、拒绝或过期保留原凭据。卸载只移除当前 Profile 的固定程序及服务注册，保留本地数据、配置和 Cloud 登记；核实移除后可恢复安装，必要时走绑定原 Agent 的浏览器授权。

真实清单使用当前生命周期已验证的 Local/SSH Runtime，经固定 Native CLI `desktop capabilities --profile ... --server ... --agent-id ... --boot-id ...` 查询同用户管理端点。请求绑定当前目标、生命周期 operation、Profile、Cloud origin、Agent ID 与 Boot ID；Agent 在读取前后验证运行身份，Desktop 在结果返回后再检查原会话仍就绪。旧版程序不支持协议、权限不足、断线或身份改变均显示不可用，不退回生产 Profile、Cloud 转发、私有文件扫描或示例清单。

Agent 复用 Console 的已发布 MCP/API 目录、批准修订校验和受管 npm 安装事实。已登记的 MCP/API 即使发生已确认故障仍应保留，以便用户查看和处理；npm 的已安装状态必须同时得到当前顶层依赖声明与实际安装元数据支持，缓存、传递依赖和市场记录不构成已安装证据。直接依赖已声明但安装缺失或无效时，可作为异常条目显示，不冒充已安装。安装、批准、扩展启用与执行健康是不同事实；此列表不授予调用或维护权限。清单和状态仅返回稳定资源 ID、名称、类型、批准修订及有界事实，不返回路径、凭据或未批准配置。

每次读取最多返回 200 条，超出或依赖校验/能力同步不完整时标记 partial。确认完整且无条目才展示空清单；partial 的空结果与不可用独立显示。进入工作区及维护结束后由 Desktop Go 立即检查，在窗口可见时以 15 秒间隔串行读取轻量状态；完整清单和详情按需读取，隐藏窗口、离开或切换目标时取消原查询并丢弃迟到响应。旧版 Native 沿用已有只读清单，不臆测状态。预览数据仅在明确的 development 工作区预览使用。实施及验收记录见 [能力管理](../development/desktop-capabilities.md)。

### 能力状态与提示

巡检调度、版本比较、缓存、角标及操作进度属于 Desktop；Agent 只通过固定管理接口返回批准修订与已有的连接、装载、发布和安装事实，不为巡检新增定时任务、业务探针或调用链记录。MCP 依据实际断线或启动失败，API 依据已批准配置的装载/发布结果，npm 依据受管安装及已启用扩展的装载结果。API 缺少连接证据时显示「连通性未验证」。MCP/API 仅提示 Agent 已记录的待批准配置。

Desktop 只对已确认使用公开 npm 源、且能确认当前发布通道的已安装包检查版本，按通道查询并缓存 24 小时；来源或通道不明时不向 Registry 发送包名，也不推断更新。能力管理卡片右上角以红色「异常」、黄色「建议」显示最高优先级，前者优先；无提示时隐藏。清单保留所有可确认的条目提示，详情显示原因、观察时间及对应操作，未知不当作故障。

### 能力详情与操作

详情沿用已确认的二级页面：顶部返回及直接操作，展示能力身份、可视化配置、JSON 和实际提供的工具或接口。配置只读；JSON 明确标注敏感值已隐藏，不能称为未经处理的完整原始文件。敏感值不进入 Desktop WebView、日志或命令参数；未知字段默认隐藏。npm 展示已核实的直接依赖及安装信息，安装状态不代表扩展已启用。读取失败、对象变更或旧版 Agent 不支持时明确反馈，不使用预览数据代替。

MCP 提供单连接重连，stdio 仅重启该服务进程；存在在途调用、任务或订阅时返回忙碌，重新握手并发布工具后才显示成功。MCP/API 移除与 npm 卸载、指定版本更新统一使用 Desktop 确认弹窗，不跳转 Cloud 审批。列表悬停及详情操作绑定同一 Local/SSH 目标、Profile、Agent/Boot 身份、能力 ID 与修订；旧身份或不支持本地维护协议的 Agent 禁用操作。MCP/API 复用热移除机制，核对能力清单后显示结果，不重启 Agent；npm 复用受管包执行器，确认修改成功后安全重启，核验同一 Agent ID、新 Boot ID、执行引擎就绪和实际包清单。

Desktop 主动维护通过当前 OS 用户受限的 Native 管理通道执行；SSH 使用目标机已验证身份。Agent 在执行时复查当前绑定、修订、维护互斥和在途任务；不得伪造 Host Grant、Run 或 Cloud 用户会话。npm 重启前重新核实在线状态及空闲条件，若包已修改而重启不能确认，分别提示，不自动重复卸载或更新。断线、超时或回读不完整为结果未知，先重新检查；不自动重放。AI Host 原有 Cloud 审批、安装/恢复授权保持不变。Skills/Scripts 保留本机 prepare/commit 安全凭据、路径约束与一次确认，不重启 Agent；SSH 环境移除只清理 Desktop 连接配置及保存的凭据，保留主机信任、不停止远程 Agent，维护期间不得移除或断开正在执行操作的环境。

### 运行活动

工作区的「运行活动」使用现有二级页面与标题栏。返回入口下直接显示统一列表，不显示页面标题或状态分组标题；等待输入和其他进行中的记录排在已结束记录之前。条目显示实际名称、状态、时间及可确认的项目身份。进入某次 Run 后展示状态、已知的等待事项或错误、时间线与运行信息，并提供执行脚本、输入参数、运行日志、执行结果和资源与产物五个独立只读阅读入口。返回时恢复上一级滚动位置和焦点；不通过展开或刷新重新执行脚本。

真实工作区通过当前 Local/已认证 SSH 目标及 Native 同用户受限管理通道直接读取 Agent 自有运行记录；不要求单独 Cloud 用户登录，也不经 Cloud 转发。该通道依据本机当前系统用户或远端已认证用户的 Agent 管理身份，只提供固定的历史、详情及有界快照读取。Agent 校验 Profile、来源、Agent ID、Boot ID 和持久化的 Run/Work 归属，读取前后核对原工作目录的当前系统访问与目录身份；工作目录无法验证时该记录不可见并标记不完整。这是独立于 Cloud/MCP 调用者的本地管理权限，不构造或复用伪造的 Cloud owner session，也不改变 Cloud/MCP 的既有调用者和项目权限。Desktop 不读取 Agent 私有数据库或快照文件。

脚本、输入和日志只从对应 Run 的留存快照按需分段读取，绝不读取同名当前脚本冒充历史；结果和资源显示实际留存信息，不刷新传输凭据。单次快照请求最多 16 KiB，阅读器累计最多 256 KiB，截断、权限不足、记录过期、目标变更或不支持协议时明确标记为不完整或不可用。列表按页读取并允许加载更早记录；管理身份或生命周期检查变化时丢弃旧结果。只在 development 工作区预览使用示例，示例与真实数据隔离。实施和验收状态见 [运行活动](../development/desktop-activity.md)。

## Agent 生命周期真实接线

本阶段将原先独立预览的环境检查、初始化授权、连接恢复、启动、升级观察、定向修复和就绪工作区串联到实际 Local/SSH 环境。仅在 Desktop Bootstrap 就绪、目标实际可用且非开发预览时接线；目标切换、连接失效或检查重启均使旧结果失效。

### 受限管理协议与执行边界

- Native 提供管理协议 v1，使用 Unix 同用户私有 socket 或 Windows 当前用户 SID 保护的命名管道，nonce 请求与响应关联；拒绝跨 Profile、来源、平台、架构或身份不匹配的事实。Desktop 经已认证目标执行受限 Native CLI，不直接读写 Agent 的配置、数据库、就绪文件或内部日志。
- Desktop 不为凭据检查直接调用 Cloud；Agent 已验证的本地管理状态与 Cloud 连接状态分别呈现。未确认的网络错误不等同于失效凭据。Desktop 直接发往 Cloud 的请求限于安装、恢复连接等浏览器授权配套的一次性请求；客户端主动能力维护不再创建 Cloud 审批请求。
- 固定 Profile 目录、目标身份、制品版本、授权批次、操作 ID 及修订号。授权、安装、恢复、启动和修复互斥；写操作前复检，失败或结果未知时不自动重放。退出目标仅取消未消费授权，已执行操作必须确认真实结果。
- 新安装经 Cloud Manifest 与安全安装器版本门禁，确认实际磁盘可用空间下界（制品大小两倍），授权后复查。PKCE + 127.0.0.1 回调，一次性兑换；Token 只经 native 内存及 stdin，远端通过已认证 SSH 标准输入传递，不进入 URL、argv、环境变量、WebView 或普通日志。安装器以独占方式创建新 Profile，拒绝已有目录或服务冲突，不以初始化名义覆盖旧环境。缺少新版 Cloud/Native 契约时明确阻断。
- 已安装 Agent 凭据恢复在浏览器明确批准后，重新检查同一目标与 Profile；只停止已核实的该 Profile 系统服务，并确认管理连接已消失，再由 Native 验证新凭据、原子更新配置并回读。若服务本来缺失，只恢复配置并转入缺失服务修复；服务身份、配置或停止结果未知时阻断。已知原 Agent ID 会绑定到 Cloud restore intent，服务端在 Token 轮换前拒绝不匹配的选择；旧 Agent ID 未知时，浏览器明确提示用户核对主机与平台。
- 定向修复只补齐已确认缺失的固定 Native 程序或用户服务。程序由 Cloud 制品校验后暂存，Native helper 再核对版本、平台、哈希和身份，无覆盖发布；服务仅新建缺失的 profile 专属定义。已有损坏程序、未知目录、权限、配置冲突、服务定义冲突或不具备安全修复依据时阻断，由用户先检查。不会停止未知进程、删除用户数据或自动重置凭据。
- 系统服务使用现有 launchd / systemd --user / Windows Task Scheduler。启动请求受理与 Agent 就绪分开；启动中、连接中、升级、失败、未知分别呈现。升级继续由 Agent 自身执行，Desktop 只观察实际阶段及重新检查版本；不创建第二套升级器。
- 进入工作区须验证实际进程的 Boot ID、Agent ID、Profile、实际运行版本及管理连接；Cloud 在线、运行能力健康是独立状态。观察期间发现目标身份变化或连接不确定时退出真实工作区并复检，不能沿用旧健康摘要。开发版 `--preview-agent-start` / `pnpm preview:agent-start` 仅用于视觉状态检查，生产版不开放。

真实 UI 统一使用 AgentLifecycleView，复用 BootstrapView 既有主题、Nexum 字标、进度组件与 DESKTOP 底标。生命周期阶段由 Go 快照和 Local/SSH Runtime 的 allowlisted progress marker 驱动，Node/Host 进度由同用户 Native 受限接口观察。仅在可信总字节量存在时显示确定进度和实际已下载量；历史仅记录观察到的阶段，默认折叠，不伪造未发生、已完成或剩余步骤。

## 应用设置与国际化

设置是 Desktop 应用级页面，不属于当前 Agent。主题（system/light/dark）和语言（system/zh-CN/en-US）均由独立 Desktop SQLite 保存，Go 校验后写入成功才更新界面。语言资源集中于 `frontend/src/i18n.ts`，跟随系统时选择系统语言偏好中第一个受支持语言，无匹配使用 English；显式设置优先，React 页面即时切换文案和文档 lang。原生托盘菜单跟随同一语言偏好；系统语言由前端使用相同的解析规则同步为进程内提示，显式已保存偏好优先。设置页面采用扁平分组列表（外观与语言、常规、通知、数据与诊断、关于客户端），不为分组添加卡片边框或背景，内容可滚动，标题栏固定。关于区域显示真实 Desktop 应用名、版本和发行通道，使用系统浏览器打开 Nexum 网站和源码仓库。设置状态与当前 Agent 选择独立；选择 Agent 不退出设置页。启动或更新期间不能通过标题栏进入设置。

常规及通知设置在 Production / Development 均接入真实后端。登录时启动以操作系统状态为准，不将 SQLite 偏好冒充实际注册；macOS 13+ 使用本应用 Bundle ID 的 SMAppService，12 使用独立且精确匹配自身的 LaunchAgent；Windows 使用 HKCU Run 中当前 Profile 专属值，明确区分已注册与系统 Startup Apps 是否允许启动。注册及撤销后回读实际状态；无法确认时不报告成功。关闭窗口行为默认隐藏到托盘，可切换为退出 Desktop；原生及自绘关闭按钮均经同一窗口关闭钩子，退出不停止 Agent。

通知采用应用偏好和系统权限双层判断。总开关默认关闭，异常及操作结果偏好默认开启；关闭总开关禁用子项但保留原值。仅在用户主动启用通知或发送测试通知时请求 macOS 授权；Windows 通过 WinRT ToastNotifier.Setting 查询系统权限，不采用固定 true 的授权占位。发送使用 Wails 原生通知服务，按总开关、类别及权限过滤；发送测试仅表示系统接口已接受请求，不代表已显示横幅。当前异常及结果事件对应已接通的 Desktop 登录项操作和诊断错误；Agent 业务事件在其真实接入后再纳入。通知失败不改变原操作结果。数据及诊断入口仅接受 data/logs 语义参数，打开当前 Profile 固定目录。设置读写或原生调用失败后回读权威状态，不猜测或自动重试可能已生效的操作。强制更新和 Agent 配置不由这些通知开关控制。

Desktop Profile 与 Agent Profile 是不同对象。Desktop 基础阶段不会连接、启动、停止或升级任一 Agent。未来连接具体 Agent 时须显式选择目标身份与环境，不能因 Desktop Profile 推断或混用 Agent 凭据；开发任务不得误操作生产 Agent。

Wails 在创建 Application 时取得当前 Profile 的单实例锁；只有首实例打开 SQLite。第二实例只通知首实例恢复窗口。关闭窗口依据当前 Profile 保存的 hideOnClose 配置隐藏至托盘或退出，Quit 仅终止 Desktop。Windows WebView2 数据目录按 Profile 设置；macOS 通过独立 .app Bundle ID 区分原生 WebView，业务数据不保存在 WebView。

## SQLite

采用纯 Go 驱动 `modernc.org/sqlite`，不引入 Node 或另一个常驻数据库服务。SQLite 文件为 Profile 数据根的 `desktop.sqlite`，Schema 2 保留版本 1 的 `settings` 表（profile、theme、可选 language、hideOnClose、desktopNotifications、errorNotifications、resultNotifications），并新增 `environments` 和 `ssh_host_keys`（非秘密连接元数据与主机指纹）。以 `application_id`、`user_version` 和保存的 profile 校验身份，拒绝未知、外部、另一 Profile 及更高 Schema。首次创建在独立临时目录完成事务后以不覆盖已有目标的方式发布；低版本仅执行内嵌连续 Migration。当前为真实 Schema 2；新增表均服务于实际环境管理。实际迁移前用 VACUUM INTO 生成一致快照并验证身份/quick_check；按版本顺序在一个事务中执行 SQL、更新 user_version、检查 quick_check、外键和配置值，再提交。失败回滚并保留备份，不自动覆盖未知或损坏的数据库。迁移备份保留用于诊断/恢复，不在启动时盲目删除。数据库、日志及目录检查拒绝符号链接落点；该约束用于防止应用误读写，不是抵抗拥有同一 OS 用户权限的恶意进程的安全沙箱。连接配置存储于当前 Profile 的 SQLite，秘密仅按用户显式选择写入系统凭据库；真实系统凭据验收与主应用接线尚待完成。

Go 绑定提供 GetBootstrapState、RetryBootstrap、QuitDesktop、OpenManualUpdate，以及原有 Info、Settings、SetTheme、SetLanguage、SetPreference、SetLaunchAtLogin、OpenDiagnosticDirectory、SendTestNotification。语言与四项布尔偏好均使用现有键值表的可选记录；兼容旧数据库，无 schema 升级。只允许合法主题、语言及明确列举的偏好键，后端保存成功后更新 UI；登录注册与通知授权读取操作系统状态。日志记录真实启动、存储就绪、前端首次成功读取、系统操作错误、测试通知受理及退出，不采集 Agent 内容。

## 构建与发行

同一仓库、独立发行：Desktop 本地构建与 GitHub Actions 采用原生 macOS/Windows x64/ARM64。CI 构建两个 Profile 候选、检查源码和依赖锁；tag 触发发行工作流按后缀选择 Profile，汇总四平台制品、校验 SHA-256 与原生构建元数据、生成双通道 Ed25519 签名清单、签名门禁、创建和公开 GitHub Release。稳定发行须 Developer ID/Apple 公证与 Windows Authenticode；本地候选签名不代表正式发行。禁止通过 Desktop 工作流改变现有 npm 发布和 Cloud 制品。此仓库当前未确定开源许可证，本次不变更许可。

## Agent 生命周期实施补充（2026-11-27）

- Cloud 安装授权区分 initialize/restore。restore 禁止创建 Agent；若 Desktop 已知原 Agent ID，会将 expectedAgentId 固定在 Cloud 请求中，Web 仅展示匹配目标，Cloud 在签发 code 和轮换 Token 前校验不匹配；未知原身份时页面明确提示核对主机与平台。
- 已安装 Agent 凭据恢复在用户浏览器明确批准后，重新检查同一目标和 Profile；仅停止已核实的当前 Profile 服务并确认管理连接消失，再由 Native 验证新凭据、原子更新配置和回读。服务缺失时只恢复配置并转入服务修复；未知服务、配置或停止结果阻断。
- Native/安装器通过 allowlisted progress marker 反馈真实安装、停止、恢复和修复阶段，Local/SSH Runtime 解析后由 Desktop 状态机驱动 UI；这些是阶段事件，不代表下载百分比。
- Native Agent 制品继续沿用 Cloud HTTPS Manifest、大小、SHA-256、平台和架构校验；没有引入 Ed25519 Native 发布签名门禁。
